## Global Constraints

- All public source is TypeScript (`.ts`/`.tsx`) with strict typechecking.
- Common consumer usage must not require duplicate interfaces, repeated type arguments, `any`, or casts to connect the contract, columns, filters, query factory, and renderer.
- Infer row/filter/sort/request/response/value types from schemas/helpers; no second column DSL, cache, or request-state mirror.
- TanStack Table v9, TanStack Query v5, Zod v4; use public exports only. Confirm exact available versions/API compatibility in Task 1, not stale v8/alpha assumptions.
- Support React in Next.js, TanStack Start, and Vite; transport, routers, authorization, and tenant scope are application-owned.
- Page input `{ pagination: { pageIndex, pageSize }, sorting, filters }`; output `{ rows, rowCount }`.
- Cursor input `{ pagination: { cursor: string | null, pageSize }, sorting, filters }`; output `{ rows, nextCursor: string | null }`.
- The default page size is 25, with a default maximum of 100; domain builders may configure limits.
- Sorting `{ id, desc }`, allowlisted backend keys, duplicate rejection, three-state cycle, multi-sort; backend results retain backend order.
- Immediate filter mode by default; search debounce defaults to 300 ms; Apply commits a validated whole draft atomically.
- Selection is explicit IDs or opt-in `allMatching` with applied-filter snapshot and excluded IDs; header checkbox affects the visible page only.
- Variants `default`, `striped`, `bordered`, `plain`; densities `compact`, `comfortable` (default); presentation never changes server behavior.
- Default empty/error rendering uses existing Empty/ErrorState inside valid table cells; no prerequisite generic Table/Pagination/ScrollArea/Skeleton item.
- Schema modules are server-safe and Zod-only; interactive modules declare client boundaries; distributed imports never reference website internals.
- Deferred scope remains deferred: virtualization/infinite scroll, resizing/pinning/DnD, trees/grouping, spreadsheet editing, backend bulk jobs/snapshots.
- Preserve theme tokens, native semantics/refs/events, localized accessible names, and established docs/playground/distribution conventions.
- No additional dev/Storybook server, Playwright, worktree, delegation, commit, merge, push, or unrelated repair without the relevant explicit authorization.

### Public API agreement

Task 1 must compile the concrete declarations before other tasks rely on them. Do not promise a native Table signature that has not been inspected. Its passing consumer fixture is the durable API agreement; equivalent internal generic decomposition is allowed.

```text
// Schema module; actual Zod schemas, not an opaque parse wrapper.
createDataGridContract({ pagination, row, filters, sortBy, pageSize?, maxPageSize? });
createDataGridPagePaginationSchema({ pageSize?, maxPageSize? });
createDataGridCursorPaginationSchema({ pageSize?, maxPageSize? });
createDataGridSortingSchema(sortBy);
createDataGridPageOutputSchema(row);
createDataGridCursorOutputSchema(row);
createDataGridSelectionSchema({ filters, id });
// Inferred aliases, each taking typeof contract:
// DataGridInput, DataGridOutput, DataGridRowData, DataGridFilters, DataGridSortKey.

createDataGridColumnHelper(contract);
// .accessor(key, options), .accessor(compute, { id, ...options }), .display(options)
// cell({ value, row, ...nativeContext }); row is domain data, value is accessor output.

useDataGrid({
  contract, columns, getRowId, queryOptions,
  initialState?, state?, onStateChange?, filterMode?, selectionMode?,
});
// state: { request?, columnVisibility?, columnOrder?, selection? }
// onStateChange: corresponding per-slice callbacks receiving the proposed value.
// request includes pagination + sorting + applied filters as one atomic slice.
```

The controller exposes `table`, native `query`, `request`, filter draft/errors, selection, cursor navigation availability, and actions: `setFilters`, `setFilter`, `resetFilter`, `applyFilters`, `resetFilters`, `setSorting`, `setPageIndex` (page only), `setPageSize`, `nextPage`, `previousPage`, `toggleRow`, `togglePage`, `selectAllMatching`, `clearSelection`. `getFilterBinding(field)` returns the inferred value/change/reset/error binding. Page-only actions must not typecheck on cursor grids. `selectionMode` is `"none" | "explicit" | "allMatching"`, default `"none"`; enabling selection always requires stable IDs. Controller default rendering availability is factored once rather than recomputed inconsistently by controls.

Rendering exports: `DataGrid`, `DataGridViewport`, `DataGridTable`, `DataGridColumn`, `DataGridRow`, `DataGridCell`. Controls export `DataGridToolbar`, `DataGridFilter`, `DataGridSearch`, `DataGridApplyFilters`, `DataGridResetFilters`, `DataGridColumnVisibility`, `DataGridPagination`, `DataGridSelectionBar`. The main UI entry re-exports controls without creating a circular dependency: shared internal context may be a small separate module. Typed binding/Table overrides carry `grid` explicitly when domain inference is needed; presentation-only controls use root context. No consumer creates a context factory or repeats domain type parameters.
