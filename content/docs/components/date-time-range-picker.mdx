## Usage

```tsx
import { DateTimeRangePicker } from "@/components/ui/date-time-range-picker";

<DateTimeRangePicker
  label="Maintenance window"
  value={range}
  onValueChange={setRange}
/>;
```

The value is a `DateRange` whose `from` and `to` are JavaScript `Date`s holding a local day and a local time of day. Pick days in the calendar, set a start and an end time, then press **Apply**. Set `clearable` to add a **Clear** action that commits an empty value immediately.

This builds on [Date Time Picker](/docs/components/date-time-picker) and shares its time field and precision rules. It differs from [Date Range Picker](/docs/components/date-range-picker), which selects whole days. `motion={false}` disables popup, Calendar, and button animations; system reduced-motion preferences take priority.

## Behavior & Accessibility

Picking days or editing either time changes a draft only. `onValueChange` fires on **Apply** with a complete `{ from, to }`, and on **Clear** with `undefined`. **Cancel**, Escape, or an outside click discards the draft; reopening always starts from the committed value. Enter inside a time field applies.

A single clicked day is a same-day range, so one day with a start and an end time is valid. Apply is disabled until days are chosen and both times are complete, and while the end is before the start, including on the same day. In that case a message (`rangeErrorLabel`) appears in a polite live region, both time fields get `aria-invalid`, and both reference the message through `aria-describedby`.

Emitted dates always have zero milliseconds, and zero seconds at the default `minute` precision. With `precision="second"` an empty end time starts at 23:59:59. `disabledDates` makes any range that would include a disabled day reset; the month bounds limit navigation. Time is not constrained.

`disabled` prevents opening and closes an open popup. `readOnly` shows the range and lets the popup open, but the calendar, both time fields, Apply, and Clear cannot change anything. `value` (including explicit `undefined`) is controlled; otherwise `defaultValue` initializes internal state. `open`/`onOpenChange` independently control visibility.

The trigger's accessible name includes the label and the displayed range. The popup has an accessible title, and each time field has its own visible label (`startTimeLabel`, `endTimeLabel`). Escape returns focus to the trigger.

## Time zone and formatting

Dates and times are read and written in the device's **local time zone**. Convert explicitly before sending a value to a server. A local time that does not exist because of a daylight-saving gap resolves to the next valid local time.

The native time fields follow the operating system's 12/24-hour setting, while the trigger follows `dateFormat` (default `"PPP p"`). Use `dateFormat="PPP HH:mm"` for a 24-hour display that matches 24-hour fields. Shortcuts and a two-month layout are not offered; use [Date Range Picker](/docs/components/date-range-picker) when you only need whole days.

This is not a native form input: serialize your range explicitly. The public API is restricted to the listed props, not arbitrary native input attributes.
