## Usage

```tsx
import { DateTimePicker } from "@/components/ui/date-time-picker";

<DateTimePicker label="Starts at" value={date} onValueChange={setDate} />;
```

The value is a JavaScript `Date` holding a local calendar day and a local time of day. Choose a day and a time as a draft, then press **Apply** to commit. Set `clearable` to add a **Clear** action that commits an empty value immediately.

This is not the [DateTime](/docs/components/date-time) component, which only displays an instant. DateTimePicker follows the [Date Picker](/docs/components/date-picker) conventions but commits transactionally, like the [Date Range Picker](/docs/components/date-range-picker). `motion={false}` disables popup, Calendar, and button animations; system reduced-motion preferences take priority.

## Consumer setup

Requires React 19.2+, Tailwind CSS 4 with shadcn theme tokens, and the declared dependencies. CLI installation includes Button (and its Loading files), Calendar, and Popover; review existing primitive overwrite prompts. Copying Source alone is insufficient for manual installation: also copy `date-time-picker-parts.tsx` and `date-time-picker-utils.ts` and install the registry dependencies. No additional animation stylesheet is needed.

## Behavior & Accessibility

Picking a day or a time changes a draft only. `onValueChange` fires on **Apply** with the merged day and time, and on **Clear** with `undefined`. **Cancel**, Escape, or an outside click discards the draft; reopening always starts from the committed value. Apply is disabled until a day is chosen; the time always holds a complete value. Enter inside a time column applies.

Emitted dates always have zero milliseconds, and zero seconds at the default `minute` precision. A controlled value with extra precision is displayed truncated and is not mutated.

`disabled` prevents opening and closes an open popup. `readOnly` shows the value and lets the popup open, but the calendar, time field, Apply, and Clear cannot change anything. `value` (including explicit `undefined`) is controlled; otherwise `defaultValue` initializes internal state. `open`/`onOpenChange` independently control visibility. `disabledDates` and the month bounds apply to calendar days only; time is not constrained.

The trigger's accessible name includes the label and the displayed value. The popup has an accessible title, the time picker is a labelled group (`timeLabel`) of listboxes named by `timeUnitLabels`. In a time column, Arrow Up/Down move one step, Page Up/Down five, and Home/End jump to the ends; the selection follows the focus. Escape returns focus to the trigger.

## Time zone and formatting

Dates and times are read and written in the device's **local time zone**. Convert explicitly before sending a value to a server, and avoid assuming a UTC instant. A local time that does not exist because of a daylight-saving gap resolves to the next valid local time.

The time columns use a 12-hour cycle (with an AM/PM column) or a 24-hour cycle. By default the locale's time pattern decides, and a 12-hour cycle applies without a locale; set `hourCycle` to override it. The trigger text follows `dateFormat` (default `"PPP p"`), so pair `hourCycle={24}` with a 24-hour format such as `"PPP HH:mm"` to keep the two in agreement.

This is not a native form input: serialize your date explicitly. The public API is restricted to the listed props, not arbitrary native input attributes. Playground Reset clears the value and closes the popup; generated code reproduces configuration rather than transient selection.
