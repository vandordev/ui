## Usage

```tsx
import {
  Drawer,
  DrawerBody,
  DrawerClose,
  DrawerContent,
  DrawerDescription,
  DrawerFooter,
  DrawerHeader,
  DrawerTitle,
  DrawerTrigger,
} from "@/components/ui/drawer";

export function ProjectSettings() {
  return (
    <Drawer swipeDirection="right">
      <DrawerTrigger>Open settings</DrawerTrigger>
      <DrawerContent>
        <DrawerHeader>
          <DrawerTitle>Project settings</DrawerTitle>
          <DrawerDescription>
            Manage the details and preferences for this project.
          </DrawerDescription>
        </DrawerHeader>
        <DrawerBody>Your settings form</DrawerBody>
        <DrawerFooter>
          <DrawerClose>Done</DrawerClose>
        </DrawerFooter>
      </DrawerContent>
    </Drawer>
  );
}
```

The registry installs editable source into your project. Use your configured UI alias if it differs from `@/components/ui`.

## Composition

- `Drawer` owns open state and configures `modal`, `swipeDirection`, `snapPoints`, and `showSwipeHandle`.
- `DrawerTrigger` opens the panel. `DrawerClose` closes it, and can wrap any button-like content.
- `DrawerContent` composes the portal, optional modal overlay, viewport, swipeable popup, and scroll-safe content region.
- A close button appears in the top-right corner by default. `DrawerHeader` reserves space so the button does not overlap the title. Set `showCloseButton={false}` on `DrawerContent` when supplying your own dismissal control, and use `closeButtonLabel` to translate its accessible label.
- `DrawerHeader`, `DrawerFooter`, `DrawerTitle`, and `DrawerDescription` provide a consistent structure. Give every drawer a title; the description is optional.
- `DrawerBody` is the flexible, vertically scrollable region with default padding. Header, footer, and the close button remain outside its scroll area.
- `DrawerPortal`, `DrawerOverlay`, and `DrawerSwipeHandle` are exported for custom compositions. If replacing `DrawerContent`, compose the Base UI viewport and popup behavior as well.

## DrawerPanel Shortcut

Use `DrawerPanel` for the common trigger, title, and panel composition. It uses the same primitives and controllers as `Drawer`; the compound API remains available for custom headers or layouts.

```tsx
import { DrawerBody, DrawerPanel } from "@/components/ui/drawer";

export function ProjectDetails() {
  return (
    <DrawerPanel
      trigger={<button type="button">View project</button>}
      title="Project details"
      description="Information about this project."
    >
      <DrawerBody>Project details go here.</DrawerBody>
    </DrawerPanel>
  );
}
```

| Prop           | Purpose                                                                                                                                                                         |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `title`        | Required title, rendered with `DrawerTitle`. Supply a meaningful accessible name.                                                                                               |
| `description`  | Optional supporting content, rendered with `DrawerDescription`.                                                                                                                 |
| `trigger`      | Optional React element composed through `DrawerTrigger`. Only this element occupies space in the page. Custom button components must forward their ref and native button props. |
| `children`     | Panel content, or a function receiving `DrawerControl`.                                                                                                                         |
| `contentProps` | `DrawerContent` props other than children, including `className`, `ref`, `finalFocus`, `showCloseButton`, and `closeButtonLabel`.                                               |
| Root props     | The same state ownership and behavior props as `Drawer`, including `control`, `swipeDirection`, `modal`, and snap points.                                                       |

`DrawerPanel` does **not** wrap children in `DrawerBody`. This lets a form own both its scrollable body and its stationary footer. For non-form content, add `DrawerBody` yourself. There is no additional trigger wrapper or hidden trigger.

### External Controller

Omit `trigger` when the opener already lives elsewhere. `useDrawer()` inside the panel still returns the supplied controller.

```tsx
"use client";

import { useRef } from "react";
import {
  DrawerBody,
  DrawerPanel,
  useDrawerControl,
} from "@/components/ui/drawer";

export function ExternalPanel() {
  const editor = useDrawerControl();
  const opener = useRef<HTMLButtonElement>(null);

  return (
    <>
      <button ref={opener} type="button" onClick={editor.open}>
        Edit project
      </button>
      <DrawerPanel
        control={editor}
        title="Edit project"
        contentProps={{ finalFocus: opener }}
      >
        <DrawerBody>Project settings go here.</DrawerBody>
      </DrawerPanel>
    </>
  );
}
```

## Forms with a Stationary Footer

Keep the native form **around** `DrawerBody` and `DrawerFooter`, not inside the body. Give it `flex min-h-0 flex-1 flex-col` so it fits the constrained panel height. Inputs scroll while the submit button stays outside that scroll region. No `DrawerForm` component or form-library dependency is needed.

```tsx
"use client";

import { useId, useState } from "react";
import type { FormEvent } from "react";
import {
  DrawerBody,
  DrawerFooter,
  DrawerPanel,
  useDrawer,
} from "@/components/ui/drawer";

export function EditProjectDrawer({
  save,
}: {
  save: (name: string) => Promise<void>;
}) {
  return (
    <DrawerPanel
      trigger={<button type="button">Edit project</button>}
      title="Edit project"
    >
      <ProjectForm save={save} />
    </DrawerPanel>
  );
}

function ProjectForm({ save }: { save: (name: string) => Promise<void> }) {
  const { close } = useDrawer();
  const nameId = useId();
  const [pending, setPending] = useState(false);
  const [error, setError] = useState<string | null>(null);

  async function handleSubmit(event: FormEvent<HTMLFormElement>) {
    event.preventDefault();
    if (pending) return;
    const name = String(new FormData(event.currentTarget).get("name") ?? "");
    setPending(true);
    setError(null);
    try {
      await save(name);
      close();
    } catch {
      setError("Could not save. Please try again.");
    } finally {
      setPending(false);
    }
  }

  return (
    <form
      className="flex min-h-0 flex-1 flex-col"
      onSubmit={handleSubmit}
      aria-busy={pending}
    >
      <DrawerBody>
        <label htmlFor={nameId}>Project name</label>
        <input id={nameId} name="name" required disabled={pending} />
        {error && <p role="alert">{error}</p>}
      </DrawerBody>
      <DrawerFooter>
        <button type="submit" disabled={pending}>
          {pending ? "Saving…" : "Save"}
        </button>
        <button type="button" onClick={close} disabled={pending}>
          Cancel
        </button>
      </DrawerFooter>
    </form>
  );
}
```

The form owns validation, pending state, error feedback, and persistence. It closes only after saving succeeds. If closing during a mutation or with unsaved changes must be blocked, use the root `onOpenChange` event and `details.cancel()`; disabling Cancel alone does not block Escape, swipe, or the built-in X.

### React Hook Form

This integration example uses your application's installed `react-hook-form`. `FormProvider` adds context without a DOM wrapper. The native form still owns body and footer. Handle save failures through the form's root error.

```tsx
"use client";

import { useId } from "react";
import { FormProvider, useForm } from "react-hook-form";
import { DrawerBody, DrawerFooter, useDrawer } from "@/components/ui/drawer";

export function ReactHookFormFields({
  save,
}: {
  save: (values: { name: string }) => Promise<void>;
}) {
  const form = useForm({ defaultValues: { name: "" } });
  const nameId = useId();
  const { close } = useDrawer();
  const { errors, isSubmitting } = form.formState;

  const submit = form.handleSubmit(async (values) => {
    form.clearErrors("root");
    try {
      await save(values);
      close();
    } catch {
      form.setError("root", { message: "Could not save. Please try again." });
    }
  });

  return (
    <FormProvider {...form}>
      <form
        className="flex min-h-0 flex-1 flex-col"
        onSubmit={submit}
        aria-busy={isSubmitting}
      >
        <DrawerBody>
          <label htmlFor={nameId}>Project name</label>
          <input
            id={nameId}
            {...form.register("name", { required: "Enter a project name." })}
            aria-invalid={!!errors.name}
          />
          {errors.name && <p role="alert">{errors.name.message}</p>}
          {errors.root && <p role="alert">{errors.root.message}</p>}
        </DrawerBody>
        <DrawerFooter>
          <button type="submit" disabled={isSubmitting}>
            Save
          </button>
          <button type="button" onClick={close} disabled={isSubmitting}>
            Cancel
          </button>
        </DrawerFooter>
      </form>
    </FormProvider>
  );
}
```

Mount `ReactHookFormFields` as a child of `DrawerPanel`, just like `ProjectForm` above.

### TanStack Form

This example uses your application's installed `@tanstack/react-form`. Subscribe to form state for the footer without moving it outside the native form.

```tsx
"use client";

import { useId, useState } from "react";
import { useForm } from "@tanstack/react-form";
import { DrawerBody, DrawerFooter, useDrawer } from "@/components/ui/drawer";

export function TanStackFormFields({
  save,
}: {
  save: (values: { name: string }) => Promise<void>;
}) {
  const { close } = useDrawer();
  const nameId = useId();
  const [error, setError] = useState<string | null>(null);
  const form = useForm({
    defaultValues: { name: "" },
    onSubmit: async ({ value }) => {
      setError(null);
      try {
        await save(value);
        close();
      } catch {
        setError("Could not save. Please try again.");
      }
    },
  });

  return (
    <form
      className="flex min-h-0 flex-1 flex-col"
      onSubmit={(event) => {
        event.preventDefault();
        event.stopPropagation();
        void form.handleSubmit();
      }}
    >
      <DrawerBody>
        <form.Field
          name="name"
          validators={{
            onChange: ({ value }) =>
              value.trim() ? undefined : "Enter a project name.",
          }}
        >
          {(field) => (
            <>
              <label htmlFor={nameId}>Project name</label>
              <input
                id={nameId}
                name={field.name}
                value={field.state.value}
                onBlur={field.handleBlur}
                onChange={(event) => field.handleChange(event.target.value)}
                aria-invalid={!field.state.meta.isValid}
              />
              {field.state.meta.errors.map((message, index) => (
                <p key={index} role="alert">
                  {message}
                </p>
              ))}
            </>
          )}
        </form.Field>
        {error && <p role="alert">{error}</p>}
      </DrawerBody>
      <DrawerFooter>
        <form.Subscribe
          selector={(state) => [state.canSubmit, state.isSubmitting]}
        >
          {([canSubmit, isSubmitting]) => (
            <>
              <button type="submit" disabled={!canSubmit || isSubmitting}>
                Save
              </button>
              <button type="button" onClick={close} disabled={isSubmitting}>
                Cancel
              </button>
            </>
          )}
        </form.Subscribe>
      </DrawerFooter>
    </form>
  );
}
```

Mount `TanStackFormFields` inside `DrawerPanel`. If your own `AppForm` already renders a native form, apply the same layout class to that component instead. Never nest another form around it. Any DOM wrapper between the panel and form must also preserve the constrained flex layout.

For a form reused outside drawers, pass `onSuccess={close}` through `DrawerPanel`'s render function instead of calling `useDrawer()` inside that form. Keep hooks inside components, not inside the render callback. Choose **panel-form** and enable **Long content** in the playground to inspect the stationary footer.

## Direction and Snap Points

The default `swipeDirection` is `right`, which opens a side panel from the right edge. Set it to `left`, `up`, or `down` for the other edges. Side drawers have a responsive width capped at `28rem`; vertical drawers use the available viewport height and can scroll.

For a vertical drawer, pass snap points as fractions between `0` and `1`:

```tsx
<Drawer swipeDirection="down" snapPoints={[0.5, 0.9]} showSwipeHandle>
  {/* trigger and content */}
</Drawer>
```

The active snap point and swipe gestures are managed by Base UI. `showSwipeHandle` adds a visual grabber; it is optional and does not replace the gesture area. Snap points are most useful with `up` or `down` drawers.

## Controlled State and Modal Behavior

Use `defaultOpen` for an initially open, uncontrolled drawer. Use `open` and `onOpenChange` when application state must control it. Base UI root props, including `disabled`, `actionsRef`, and change event details, are forwarded.

```tsx
"use client";

import { useState } from "react";
import {
  Drawer,
  DrawerClose,
  DrawerContent,
  DrawerHeader,
  DrawerTitle,
  DrawerTrigger,
} from "@/components/ui/drawer";

export function ControlledDrawer() {
  const [open, setOpen] = useState(false);

  return (
    <Drawer open={open} onOpenChange={setOpen}>
      <DrawerTrigger>Open settings</DrawerTrigger>
      <DrawerContent closeButtonLabel="Close settings">
        <DrawerHeader>
          <DrawerTitle>Settings</DrawerTitle>
        </DrawerHeader>
        <div className="p-4">
          <DrawerClose>Done</DrawerClose>
        </div>
      </DrawerContent>
    </Drawer>
  );
}
```

Drawers are modal by default: they render a backdrop and use Base UI's modal focus management. Set `modal={false}` only when the surrounding interface should remain interactive. Non-modal drawers omit the backdrop, so provide suitable dismissal and focus behavior for your use case.

## Scrollable Body

Use `DrawerBody` instead of manually adding overflow classes. It forwards native `div` props, including `ref`, and accepts `className` overrides.

```tsx
<DrawerContent>
  <DrawerHeader>
    <DrawerTitle>Project settings</DrawerTitle>
  </DrawerHeader>
  <DrawerBody>
    {Array.from({ length: 30 }, (_, index) => (
      <p key={index} className="mb-4">
        Setting {index + 1}
      </p>
    ))}
  </DrawerBody>
  <DrawerFooter>
    <DrawerClose>Done</DrawerClose>
  </DrawerFooter>
</DrawerContent>
```

The panel constrains its height to the viewport. `DrawerBody` uses `min-h-0 flex-1 overflow-y-auto`, so only the body scrolls. Enable **Long content** in the playground to try it.

## Drawer Controls

`useDrawerControl()` creates a stable controller for one mounted Drawer. `useDrawer()` selects the nearest Drawer; `useDrawer(control)` selects a specific controller instead. All three return `DrawerControl`:

| Member    | Type                  | Behavior                              |
| --------- | --------------------- | ------------------------------------- |
| `isOpen`  | `boolean` (read-only) | Reactive state of the mounted Drawer. |
| `open()`  | `() => void`          | Requests opening through Base UI.     |
| `close()` | `() => void`          | Requests closing through Base UI.     |

### Control from Outside

```tsx
"use client";

import { useRef } from "react";
import {
  Drawer,
  DrawerBody,
  DrawerContent,
  DrawerHeader,
  DrawerTitle,
  useDrawerControl,
} from "@/components/ui/drawer";

export function SettingsDrawer() {
  const control = useDrawerControl();
  const opener = useRef<HTMLButtonElement>(null);

  return (
    <>
      <button ref={opener} type="button" onClick={control.open}>
        Open settings
      </button>
      <Drawer control={control}>
        <DrawerContent finalFocus={opener}>
          <DrawerHeader>
            <DrawerTitle>Settings</DrawerTitle>
          </DrawerHeader>
          <DrawerBody>Your settings form</DrawerBody>
        </DrawerContent>
      </Drawer>
    </>
  );
}
```

An ordinary external button is not an associated Base UI trigger. Use `finalFocus` to explicitly restore focus to it. Prefer `DrawerTrigger` inside the root when you do not need external control.

### Control from a Child

```tsx
import { useDrawer } from "@/components/ui/drawer";

export function SaveSettings({ save }: { save: () => Promise<void> }) {
  const { close } = useDrawer();

  async function handleSave() {
    await save(); // The drawer stays open if saving fails.
    close();
  }

  return (
    <button type="button" onClick={handleSave}>
      Save settings
    </button>
  );
}
```

Place `SaveSettings` inside `DrawerBody`. Handle loading and save errors in your form before closing. Unlike `DrawerClose`, this waits for the action to succeed. A hook-bound child depends on being inside a Drawer; reusable forms can instead accept an `onSuccess` callback.

### Render Function Shortcut

```tsx
<DrawerContent>
  {({ close }) => (
    <>
      <DrawerHeader>
        <DrawerTitle>Settings</DrawerTitle>
      </DrawerHeader>
      <DrawerBody>Your settings form</DrawerBody>
      <DrawerFooter>
        <button type="button" onClick={close}>
          Done
        </button>
      </DrawerFooter>
    </>
  )}
</DrawerContent>
```

The render function receives the same controller as `useDrawer()`. Call hooks at the top level of a component, not inside this callback.

### Ownership, Nesting, and Lifecycle

- Without `control`, each `Drawer` manages its own state (or uses the existing `open` / `onOpenChange` API). It never inherits another Drawer's state.
- `useDrawer()` selects the nearest root, including through portals. In nested drawers, `useDrawer(outerControl)` explicitly selects the outer one. Outside a root, pass a control or the hook throws a descriptive error.
- One controller binds to one mounted Drawer. Sharing it between simultaneous roots throws an error. A controller can be reused after its previous root unmounts.
- Do not combine `control` with `open`, `defaultOpen`, or `handle`. Types and runtime checks reject ambiguous state ownership. `onOpenChange` remains available for observation or cancellation.
- `isOpen` is `false` before attachment and after unmount. Actions before mount or after unmount are ignored, not queued; Base UI emits a development warning. Invoke actions in event handlers or effects, never during rendering.
- `open()` and `close()` go through Base UI's imperative actions and emit `onOpenChange` with reason `imperative-action`. `details.cancel()` can reject either request without desynchronizing the controller.
- With a controlled `open` prop, `useDrawer().close()` requests a change; the panel remains open until the parent updates the prop.
- `close()` returns `void`, not a promise for the exit animation. Use `onOpenChangeComplete` for work that must wait for animation completion.

```tsx
<Drawer
  control={control}
  onOpenChange={(nextOpen, details) => {
    if (!nextOpen && hasUnsavedChanges) details.cancel();
  }}
>
  {/* trigger and content */}
</Drawer>
```

## Accessibility and Interaction

- Base UI provides dialog semantics, focus management, Escape dismissal, and focus restoration to the trigger.
- `DrawerTitle` supplies the accessible name. Use `DrawerDescription` for supporting context, not as a replacement for the title.
- Triggers and close controls should remain keyboard-operable and have clear accessible names. Icon-only controls need an `aria-label`.
- The built-in X uses a compact 32px button with a visible keyboard focus ring and an accessible label. Keep a visible close control even when swipe dismissal is available.
- Touch users can drag the popup toward its closing edge. The modal overlay follows swipe progress, and reduced-motion preferences disable CSS transitions.
- Keep long content in `DrawerBody`; the popup content region constrains overflow and scrolling.
- The portal stays within the drawer's theme scope, which helps preserve inherited theme variables and nested drawers.

See the [Base UI Drawer API](https://base-ui.com/react/components/drawer) for all supported root and primitive props.
