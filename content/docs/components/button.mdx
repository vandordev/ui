## Usage

```tsx
import { Button } from "@/components/ui/button";

export function Demo() {
  return <Button variant="outline">Button</Button>;
}
```

Use your project's configured UI alias if it differs from `@/components/ui`.

## Examples

### Variants

The six built-in variants are `default`, `secondary`, `outline`, `ghost`, `destructive`, and `link`.

Solid variants use a subtle top-to-bottom gradient and thin border, without shadows. Outline keeps its border; ghost and link stay flat. All variants retain a keyboard focus ring.

### Sizes

Use `xs`, `sm`, `default`, or `lg` for text buttons. Icon-only buttons use `icon-xs`, `icon-sm`, `icon`, or `icon-lg`. Give icon-only buttons an accessible label.

</ComponentPreview>

### With Icons

Use `data-icon="inline-start"` or `data-icon="inline-end"` to indicate an icon's position. Icon sizing is handled by the Button.

<ComponentPreview name="button-icon" title="button-icon.tsx">
  <ButtonIcon />
</ComponentPreview>

### Disabled

Use the native `disabled` prop to prevent interaction.

<ComponentPreview name="button-disabled" title="button-disabled.tsx">
  <ButtonDisabled />
</ComponentPreview>

### Loading

Set `isLoading` while an action is pending. The Button shows the Loading component's default `arc` before its label, becomes disabled, and sets `aria-busy`. Icon-only sizes replace their icon with the spinner and retain the supplied `aria-label`.

```tsx
<Button isLoading={isSaving}>Save</Button>
```

Installing Button also installs Loading through its registry dependency. The loading indicator inherits the button's color and respects reduced-motion preferences. The playground's **Is Loading** toggle updates both the preview and generated code.

<ComponentPreview name="button-loading" title="button-loading.tsx">
  <ButtonLoading />
</ComponentPreview>

### As Child

Use `asChild` to style a link without nesting it inside a button. The child retains its native link semantics. Use this for navigation, not the `variant="link"` appearance alone.

Base UI's `render` composition is also supported:

```tsx
<Button
  render={<a href="/docs/components" />}
  nativeButton={false}
  variant="outline"
>
  Browse components
</Button>
```

## Storybook Stories (Optional)

Add editable stories to **your existing React Storybook**. This is a stories file, not a hosted Storybook or a replacement for your configuration. The normal Button installation does not include it.

Install Button first using the Installation instructions above, then run:

```bash
npx shadcn@latest add https://vandor-ui.vercel.app/r/button-stories.json
```

The stories-only item installs `button.stories.tsx` beside Button in your configured UI directory. It does not reinstall Button or Loading, add packages, or modify `.storybook/`. If a stories file already exists, review the CLI diff rather than overwriting your customizations.

The stories import `Button` relatively (`./button`) and use only `@storybook/react` types and `lucide-react` icons. Ensure these packages are available in your project; keep `@storybook/react` on the same version as the rest of your Storybook packages. The stories are typechecked and composed against Storybook React 10.6.1; other versions are not verified. A working Button and its Loading dependency remain required.

### Discover the stories

Include your UI directory in the `stories` patterns of your existing `.storybook/main.ts`. For the default directory, add this entry without replacing your existing patterns:

```ts
"../components/ui/**/*.stories.@(js|jsx|mjs|ts|tsx)";
```

Adjust the path if your UI directory differs. In `.storybook/preview.ts`, import your application's global stylesheet so Tailwind utilities and the Button theme tokens are available:

```ts
import "../styles/globals.css";
```

Use your own stylesheet path and ensure your Storybook framework processes Tailwind CSS, including the stories directory in source scanning. The stories inherit your existing decorators and theme setup. For dark mode, apply your application's dark-theme selector inside the preview iframe; changing only the Storybook manager theme will not theme the component. The `autodocs` tag requires `@storybook/addon-docs` configured in your Storybook to show a generated Docs page; Canvas stories and Controls do not require that addon.

### Customize and compare

Under **Vandor UI / Button**, use **Playground** to edit the label, variant, size, disabled/loading state, custom classes, and accessible label. Set an `aria-label` when selecting an icon-only size. Dedicated stories show all six variants, all eight sizes, disabled/loading states, icons, native link composition, and disabled press animation. Multi-example stories disable controls for the props they demonstrate explicitly.

Edit your installed `button.tsx` to customize the component, and edit `button.stories.tsx` to add application-specific examples or rename the sidebar group. Hover, focus, and pressed states can be inspected directly in Canvas; use your browser or OS reduced-motion setting to check motion preferences. These stories do not configure automated visual regression testing.

For manual installation, copy the `content` of the stories file from the [stories registry artifact](https://vandor-ui.vercel.app/r/button-stories.json) into `button.stories.tsx` beside your installed Button. Keep the relative import, or update it if you move the file elsewhere.

## Behavior & Accessibility

The Button scales to `0.96` while pressed and returns on release, with a `0.12s` transition. Its appearance darkens by 10% while active, preserving the gradient. Hover colors and press brightness transition over `200ms`. Disabled buttons do not darken or animate. Reduced-motion preferences disable scaling and CSS transitions, but retain the instant color feedback.

Set `whileTap={false}` to turn off the press animation. Active color feedback remains enabled. Motion's animation props and callbacks are supported.

```tsx
<Button whileTap={false}>No scale feedback</Button>
```

- Native buttons support Enter and Space activation. The press animation uses Motion's pointer and Enter gestures.
- A visible focus ring identifies keyboard focus. Give icon-only buttons an `aria-label`.
- Buttons default to `type="button"`. Set `type="submit"` for form submission.
- With `asChild`, the child retains its own keyboard behavior and attributes. Use links for navigation; native `disabled` does not disable a link.
- `isLoading` blocks clicks, including on `asChild` links, and disables press feedback. The spinner is decorative; the button retains its accessible name and communicates the pending state through `aria-busy`.
